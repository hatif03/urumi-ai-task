## Which LLM and provider does your chat agent use?

`openai/gpt-oss-120b` (an open-weight model) served by **Groq** on its free tier, through Groq's OpenAI-compatible endpoint. ## Anything else we should know?

**Where to look.** `README.md` is the operator guide (local setup, VPS, placing an order, connecting an MCP client, using the chat). `docs/requirements-coverage.md` maps every line of the brief to the code and to the evidence that it works. **It runs for real.** The same chart ran on an AWS EC2 instance (t3.large, k3s) with real Let's Encrypt certificates, and the whole definition of done, the multi-store bonus and a hosted server passed there (65 of 65 scripted checks, including killing an upstream pod). The demo video shows that live deployment with two users; its narration script is `docs/demo-narration.md`. The video is generated by scripts in `scripts/demo/` (a browser and a terminal driven against the live system), and the voice is a synthetic text-to-speech voice, not a recording of a person.

**Known issues and limits.**
- The live deployment uses `sslip.io` hostnames that resolve to the server's IP, not a domain I own; the certificates are real. Pointing a real domain at it is a values change only.
- Images were copied onto the node instead of pulled from a registry. It is a single node, so there is no node-failure tolerance, and one machine cannot show throughput scaling across replicas (the autoscaler's decision from 2 to 4 replicas is shown, not linear throughput).
- Postgres is one pod with a persistent volume; backups are documented, not automated. Alert rules exist but nothing receives them.
- The store and hosted MCP servers trust the network (NetworkPolicy admits only the gateway) rather than a per-server token. Tool permissions rely on the annotations an upstream declares for "read-only".
- Chat answer quality is that of a free-tier model and varies; the brief grades the tool loop, which is tested with a fake model and shown live.
- Bun 1.2.19 crashed inside the gateway pod under load (found through crash dumps, see `docs/experiments/0006-gateway-collapse-under-load.md`); the images use Bun 1.4.3 and the same load run was clean. I did not diagnose the crash inside Bun itself.

**What I would do differently.** Push versioned images to a registry from CI with scanning and a pull secret; move secrets to an external secrets operator; use a managed or replicated Postgres with automated backups; give each upstream its own token; add an Alertmanager receiver; run on three nodes and repeat the load test; and add a regression run of the chat against the real model.
